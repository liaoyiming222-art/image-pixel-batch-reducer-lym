# 精简实时统计（2026-10-12）

此方案替代旧看板的 Cloudflare 流量归档口径。两个正式站点独立统计，共用管理员看板和 D1。

## 口径与展示

- 网站访问量：正式站点的 `page_view` 数量，打开或刷新页面计一次；不是人数或会话数。后台、本地和预览部署不采集。
- 检测图片数量：成功读取尺寸和比例的图片数量，包括压缩和比例分组两个入口。无需压缩也计入；同一队列跨工具不重复计数，重新导入计为新检测。失败读取不计入。2026-10-13 起增加压缩入口检测埋点；此前只覆盖比例分组，历史缺失不伪造补齐。
- 次级指标，处理成功图片：`image_process_finished.props.success` 之和，包括成功压缩和格式转换；跳过、失败、检测不混入。重新处理计新的业务操作。
- 总量从该站点实际首条埋点开始，不受日期筛选影响。开始时间和最后收到时间分别展示。
- 月度按北京时间自然月归属，可相加为累计；开始采集前不补零或补历史。没有事件的站点显示尚未采集。
- 首页仅访问和检测两张累计卡片、期间趋势、本月/期间数量、月度简表；压缩数量放采集状态。

## 更新流程

产品事件约 300 毫秒后发送到同源 `/api/events`，D1 入库后即可查询。相同事件编号在重试时去重。浏览器存储不可用时保留内存身份并继续上报。

`/api/admin/stats` 读取一次按天聚合的事件结果，再在内存计算累计、期间和月度；同时查询站点注册表。不调用外部 Analytics，也不等待定时汇总。看板每 10 分钟自动读取，切回后台时立即读取，并支持手动刷新。查询失败保留已读数据、提示错误，下一轮继续重试。

旧归档接口返回 410 并提示刷新页面，Worker 定时任务已撤销；部署脚本也不再生成归档定时任务。旧归档表和历史事件保留，避免丢失记录，但不参与当前看板。D1 是埋点存储，仍运行于 Cloudflare，区别是无需读取 Cloudflare 流量分析服务。

## 验证

- 57 项测试通过：事件去重、站点隔离、北京时间跨月、期间与累计区别、归档不混入、空站点、浏览器存储受限等。
- 类型检查和生产构建通过。
- 隔离浏览器运行实际 PNG 转 JPG：捕获成功处理事件；没有往生产库写测试事件。
- 看板自动轮询、手动刷新、月度导航、手机无横向溢出和无脚本错误通过；刷新没有调用归档接口。
- 线上读取测量：旧查询约 2886 毫秒，精简查询约 548 / 545 毫秒。这是当前网络的一次对比，不是服务时延保证。

通常事件上报成功后，下一个 10 分钟轮询即可看到变化。后台标签页隐藏时暂停轮询。断网、浏览器拦截或旧页面未刷新可能使上报延迟；不保证所有访问均能采集。仅打开工具或检测不产生“压缩成功”数量。

## 2026-10-13 需求澄清后的口径

主指标统一为“服务图片数”：成功读取尺寸与比例即提供服务，不要求实际压缩。同一列表内跨工具和改参数不重复计数；追加只增加新图片；清空后重新导入再次计数。沿用 inspection_finished，不重写事件或补造历史。

新增展示“成功新建文件夹数”：直接累计 folder_create_finished 的 created + children，包含实际创建的主目录、子目录。已有、跳过或未创建成功的目录不计入；部分失败保留已经实际创建的数量。旧事件已有这些字段，直接汇总即可，无需数据库迁移。

网站访问量为辅助指标。首页三张累计卡片、本期、月度表和趋势统一展示；不新增任务量、人数、漏斗，也不区分管理员自己的产品使用。保留十分钟刷新和手动读取；所有指标按站点独立统计。
