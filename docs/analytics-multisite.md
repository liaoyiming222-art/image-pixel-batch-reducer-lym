# 多站点统计

两个站点共用源码、D1 和管理员后台，通过站点标识隔离。后台选择器可切换站点，累计、月份、趋势、工具、用户和归档状态都按选择的站点查询。原后台密码不变。

| 站点标识 | 正式域名 | 流量来源 | 上线日 |
|---|---|---|---|
| pixelflow-image-tools | pixelflow-image-tools.pages.dev | Cloudflare 历史归档 | 2026-07-31 |
| pixelfloweverybody | pixelfloweverybody.pages.dev | 匿名页面访问与会话事件 | 2026-10-10 |

第二站点当前没有启用 Cloudflare Web Analytics，新增匿名访问事件可以统计未来浏览量和访问次数，但接入之前的数据无法补算。后台注明每个站点的数据来源及实际采集起点。第二站点的访问次数按会话首次发生的日期统计，避免跨日重复累计。同一浏览器在不同站点分别去重；不提供跨站点真人去重。

## 隔离与兼容

- 服务端以实际请求域名匹配已启用的站点，校验事件标识与域名一致；预览域名和未知域名拒绝采集。
- 旧主站点事件未带标识时继续归属原站点；第二站点必须带自己的标识。
- 事件、用户、会话的数据库 ID 在第二站点加命名空间，相同编号可在两个站点分别存在，重试仍幂等。原站点保留 ID，旧队列重试不会增加重复量。
- 原始事件增加 site_id；新增按 site_id 分区的汇总与历史表，原表保留便于回退。迁移前完整备份位于 `.wrangler/analytics-before-multisite.sql`，不提交到 Git。
- 后台查询、人数去重、首条事件、月度和每日数据全部带站点条件。站点切换会清除旧数据，并忽略过期请求，防止显示上一个站点的数据。
- 原始用户文件、图片、表格内容不上传，管理员查询仍需登录。

## 部署

数据库迁移用 `wrangler d1 migrations apply DB --remote`，有迁移记录，重复执行不会重复迁移。主站点使用原部署流程；同一份 dist 的第二站点可运行 `node scripts/deploy-everybody.mjs`。该脚本临时使用第二站点的标准 Wrangler 配置，完成后恢复原配置。两个项目都需要 DB 生产绑定，预览不要绑定生产数据。

两个项目连接相同 GitHub 仓库和 main 分支，后续推送可以同时部署；依据域名自动选择站点标识。第二站点 `/admin` 会跳转至主统计后台并选择第二站点。推荐始终使用现有后台或本地预览。

## 验收

54 项自动测试通过，新增覆盖：相同事件编号跨站点不碰撞、用户分别去重、站点伪装被拒绝、旧主站点兼容、历史归属与迁移保留、月度和每日分区、空站点不继承其他数据、未知站点拒绝查询、前端待发队列不串站点。上线检查还需验证切换站点、两个采集接口、原站点历史及管理员权限。
