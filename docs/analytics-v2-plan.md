# PixelFlow 统计后台优化方案与验收

## 需求与信息架构

目标：优先回答上线以来的累计情况、每个月的使用情况；首页不再陈列全部技术计数。

参考 Plausible 与 PostHog 的信息层次：少量核心指标、可筛选趋势、下钻明细。采用浅色工作台、侧边导航、四个核心数字、图表与紧凑表格，支持窄屏。

- 总览：上线以来累计浏览量、累计访问次数、埋点以来识别用户、有效使用用户；时间筛选只控制趋势和本期摘要，不改变累计卡片。
- 月度统计：逐自然月展示流量、用户及主要业务量，可点击月份查看当月趋势。
- 工具分析：压缩、检测、目录创建的主要结果；异常、无需处理和各类导出按需展开。
- 数据状态：历史覆盖、采集起点、最后更新、归档状态、统计口径。数据采集之前显示未采集，不将未知历史写成零。

## 数据口径

站点创建日为 2026-07-31。历史流量只使用 Cloudflare Web Analytics 的同一来源，不与自建页面访问、会话相加。累计卡片标注已有记录范围，未归档日期属于缺失而非零。当前日的数据可通过更新按钮拉取，归档保留最近日期覆盖更新。

业务数据从实际首条埋点日开始；旧月份业务量不可恢复。匿名用户为浏览器标识。累计、所选期间、每个月分别 COUNT DISTINCT，禁止累加月度人数得到累计人数。指标返回零代表该采集期间没有对应操作记录，不代表采集前无历史使用。

保留已有事件数据，不重写历史，不制造示例数据。后台仍需登录，原密码继续有效。本地预览读取线上数据库并排除自身埋点。

## 测试方案

1. 历史来源与自建访问重叠时不重复累加；日期筛选不改变上线累计。
2. 月份边界按北京时间处理，跨年月份正确；同用户跨月累计一次、每月分别一次。
3. 采集前业务值为 null；采集后无操作为 0；缺失归档与已归档零值不同。
4. 月度流量合计等于累计历史流量；期间合计和按日图表一致；缺失日期不连成真实零点。
5. 事件重试幂等、检测复用不重复、部分失败及目录计数保持原有测试。
6. 后台未登录拒绝访问，登录和刷新错误可恢复，快速切换日期不会被旧请求覆盖。
7. 桌面与手机浏览器截图检查；导航、月份选择、日期筛选、图表提示及详情展开可操作；无页面溢出和运行错误。
8. 正式构建、Functions 类型检查、本地真实数据联调通过后部署；线上数据不写入测试事件。
